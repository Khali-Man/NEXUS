## Visual review and regression contract

Compared the paired five-workspace captures for type/spacing, status emphasis, theme consistency, realistic empty states, clipping and scroll behaviour. The new citizen linked path provides explanatory identity; the dispatcher fallback has a clear task and source boundary; responder history no longer competes with current work; assurance leads with coverage and definitions; administration separates discovery, a selected run and retained history. New screenshots do not establish real-city routing or physical response outcomes. Phone review additionally caught intrinsic queue-card compression and fault-button wrapping inside otherwise non-overflowing pages. Those were corrected, with direct card/content and button/panel geometry assertions added. The metrics table now has a readable minimum width, a horizontal-scroll hint and a focusable keyboard scroll region.

The first rendered pass revealed a grid minimum-size problem stretching the dispatcher canvas to the entire queue height; it was corrected with a bounded grid row and scroll containment. A later pass moved detailed filters into refinements to keep more records visible at 1280/1440 widths. The expanded viewport axe check exposed a pre-existing low-contrast citizen banner link on desktop, which was corrected. Tests were kept strict: an existing global empty-message locator was scoped to the queue because the new location board truthfully has its own empty message.

Five shell baselines were intentionally reviewed and regenerated for this requested redesign. Dispatcher now covers the primary `/cad/live` surface. Declared, internally consistent fictional visual fixtures supply incidents/units, mission groups, metrics and scenario runs; functional journeys and documentation captures remain unmocked. Broad masks for maps, counts, tables, references, mission cards and runs were **removed**, as was the CSS hiding repeated cards/runs. Only the changing header clock is hidden. `maxDiffPixelRatio: 0.003` and axe severity checks are unchanged. Fixed metrics still assert means 30/60/30/180 seconds, coverage 12/9/6/3 of 16 and explicit missing measurements. Field fixtures assert current and incoming assignments plus their real milestone labels.

## Remaining limitations

- Real Osogbo road import and independent route validation remain blocked/unverified in this cloud environment. The fallback is intentionally explicit; no real-city route accuracy, live traffic or arrival guarantee is claimed. OSRM engine fixtures test routing mechanics only.
- Windows 11, non-Chromium browsers, installed mobile PWAs and manual screen-reader/device usability review remain untested. The [Windows guide](WINDOWS_11.md) is retained; CSS safe-area support is implemented, while actual notched-device behaviour is not claimed verified.
- The live queue returns at most 100 matching records; use filters/history for larger collections. The map companion shows up to eight locations at a time and declares that bound. Responder inbox/history uses the existing latest-100 assignment API bound. Metrics currently load the agency sample before client-side table navigation; very large research datasets will need server-side metric aggregation/paging.
- Stop-state recording starts with migration 006. Earlier interrupted runs are not retroactively classified; their commands still obey the authoritative incident state.
- Turning off the unit-offline injection returns unreserved units to available, as the existing control did and the new description states; it does not reconstruct earlier availability. Simulation fault flags describe injection intent, not all observed health conditions.
- Snapshot inputs deliberately freeze fictional data; this does not prove live transport, persistence or routing. Those have separate functional checks. Automated axe results do not establish a complete WCAG or manual accessibility audit.
- Existing partial requirements remain listed in [the inventory](IMPLEMENTATION_INVENTORY.md): comprehensive runtime API response schemas, richer review-evidence attachment workflow, automatic retained-history/command-TTL deletion, independent signer custody/external anchoring. This UI change does not claim to complete those.

No merge to `main`, public deployment, real emergency integration, invented performance score or assertion about improved physical response is part of this work.
